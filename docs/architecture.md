# 아키텍처와 위협 모델

## 설계 목표

FinGuard의 핵심 질문은 “어떤 소스와 아티팩트를, 누가 만든 검사 결과와 승인을 근거로, 어디에 배포하려는가”입니다. 여러 스캐너를 연결하는 것보다 입력 간의 결속과 배포 전 재검증을 우선했습니다.

## 구성 요소

1. 파서 어댑터는 Ruff, JUnit, coverage.py, Semgrep, 범용 SARIF, Trivy, CycloneDX, pip-audit, OWASP ZAP 결과를 `ScanResult`로 변환합니다.
2. 정규화 모델은 도구에 종속되지 않는 심각도와 지문(fingerprint)을 만듭니다. 스캐너 제품명과 메시지는 지문에 넣지 않습니다.
3. 스캔 증명서(scan attestation)는 보고서 해시, 스캐너 버전, 도구 URI, 전체 소스 커밋, 이미지 다이제스트, 규칙 세트 및 명령어 해시, 취약점 DB 메타데이터, 종료 코드, CI 잡, 러너, 실행 시각을 기록합니다.
4. `ReleaseSubject`는 커밋, 이미지, SBOM, 배포 위치, 상태 확인 URL, 빌더를 하나의 정규형 SHA-256으로 묶습니다.
5. 승인 증명서(approval attestation)는 전체 `ChangeRequest`와 `ReleaseSubject`의 해시를 포함하며, 운영 정책에서는 Cosign 서명을 요구합니다.
6. 정책 엔진은 입력, 정책 예외, VEX, 테스트 지표를 외부 상태를 변경하지 않고 판정합니다.
7. 게이트와 검증 CLI는 신뢰해야 하는 모든 입력을 먼저 비공개 스냅샷으로 고정합니다. 증적 생성기는 입력, 판정, 요약, 감사 체인, 매니페스트를 준비 디렉터리에 쓴 뒤 원자적으로 게시합니다.
8. 배포 제어기는 별도 스냅샷에서 증적, 서명, 정책 원문 SHA-256, 평가 시각을 다시 검증하고 승인된 대상만 롤아웃합니다. 실제 배포 결과는 별도 키로 서명합니다. 롤아웃, 스모크 테스트, 결과 기록 또는 서명에 실패하면 이전 이미지와 감사 애너테이션을 복원합니다.

## 신뢰 경계

```text
[개발자 / MR 러너]
  │  운영 키와 변경 승인에 접근 불가
  ▼
[보호 릴리스 러너] ──읽기──> [다이제스트로 고정된 도구 이미지]
  │                         [내부 패키지 미러]
  │ 단일 빌드, 보안 검사
  ▼
[FinGuard 게이트] <──공개키로 검증── [ITSM 승인 증적과 서명 번들]
  │ ──서명──> [증적 저장소]
  │                         │
  │                         └─> [WORM/SIEM 어댑터, 미구현]
  ▼
[배포 러너: 공개키만 보유] ──쓰기──> [운영 Kubernetes API]
```

MR 잡과 릴리스 잡을 분리해 신뢰하지 않는 변경이 운영 자격 증명에 접근하지 못하도록 했습니다. 게이트 서명 키와 배포 검증 키도 분리합니다. 배포 러너는 공개키만 보유하므로 스스로 PASS 증적을 만들 수 없습니다.

Jenkins 에이전트를 재사용할 때는 체크아웃 전에 전용 작업 공간을 비웁니다. 따라서 이전 빌드의 보고서나 추적하지 않는 파일이 새 판정과 이미지에 섞이지 않습니다.

## 릴리스 불변식

릴리스 게이트가 PASS하려면 다음 관계가 모두 성립해야 합니다.

```text
파이프라인 커밋 == 변경 요청 커밋 == ReleaseSubject 커밋
레지스트리 이미지 다이제스트 == ReleaseSubject 이미지 다이제스트
CycloneDX 보고서 SHA-256 == ReleaseSubject SBOM SHA-256
아티팩트 스캔 이미지 다이제스트 == ReleaseSubject 이미지 다이제스트
change.release SHA-256 == 실행 시점의 ReleaseSubject SHA-256
ITSM 승인 대상 SHA-256 == 실행 시점의 ReleaseSubject SHA-256
ITSM 승인 변경 요청 SHA-256 == 실행 시점의 전체 ChangeRequest SHA-256
배포 정책 ID/버전/SHA-256 == 증적에 기록된 정책 ID/버전/SHA-256
배포 요청 대상 == 증적의 ReleaseSubject 대상
배포 시각 - 증적 평가 시각 <= 정책이 허용한 최대 증적 나이
```

Git 객체 ID는 SHA-1이면 40자, SHA-256이면 64자인 전체 값만 허용하며 축약값 비교는 사용하지 않습니다. 이미지는 반드시 `@sha256:<64 hex>` 형식을 사용합니다.

## 판정 순서

1. 필수 범주의 스캐너가 정상적으로 사용할 수 있는 결과를 남겼는지 확인합니다.
2. 보고서 해시, 서명, 실행 시각, 커밋, 아티팩트, 러너, 키 ID, 명령어 해시, 종료 코드, 취약점 DB의 최신성을 이용해 스캔 출처를 검증합니다.
3. 여러 스캐너가 찾은 같은 이슈를 지문으로 통합하고, 확인된 심각도 중 가장 높은 값을 보존합니다. `UNKNOWN`이 이미 확인된 Critical 또는 High를 대체하지 못합니다.
4. 유효한 VEX 상태를 처리한 뒤 보상 통제, 유효 기간, 심각도, 환경, 정책 버전을 모두 만족한 예외만 적용합니다.
5. 심각도와 건수, 수정 버전, SPDX 라이선스, 단일 커버리지 보고서, 최소 테스트 수, XML 원시 집계값의 일관성을 판정합니다.
6. CB/SR 형식, 롤백 계획, 승인 역할과 시각, 직무분리를 판정합니다.
7. ITSM 승인 서명과 실행 대상을 다시 대조합니다.
8. 오류 등급 위반이 하나라도 있으면 FAIL을 반환합니다.

## 위협과 통제

| 위협 | 구현 통제 | 남은 운영 과제 |
| --- | --- | --- |
| 스캐너 실패를 탐지 결과 0건으로 오인 | 누락, `ERROR`, `SKIPPED`, 해석할 수 없는 심각도, 필수 필드 및 스키마 누락을 차단 | 미탐은 여러 도구를 함께 사용하고 규칙을 검토해 보완 |
| 악의적으로 구성했거나 지나치게 큰 보고서로 인한 파서 자원 고갈 | 50 MiB 제한, 엄격한 JSON 파싱, XML DTD 및 엔터티 거부, 링크 입력 차단 | 대규모 SBOM을 위한 스트리밍 파서 검토 필요 |
| 검증 후 원본 교체 | 게이트와 배포 명령이 먼저 비공개 입력 스냅샷을 만들고 동일한 바이트만 평가·서명·사용 | 운영 저장소 권한과 불변 아티팩트 설정 필요 |
| 다른 커밋이나 이미지의 보고서 재사용 | 서명된 출처 정보와 `ReleaseSubject` 대조, CI 도구 이미지의 서명 및 다이제스트 검증 | 스캐너별 워크로드 아이덴티티와 키 격리 필요 |
| 빌드 이전 사전 승인을 최종 아티팩트에 재사용 | 승인 시각이 `built_at`보다 늦은지 확인 | ITSM 시계 동기화와 공개키 회전 |
| CI가 외부 승인을 위조 | ITSM 개인키는 CI에 제공하지 않고 Cosign 공개키로만 검증 | 실제 승인자 직무는 IdP API로 확인 필요 |
| 판정 파일 변조 | 모든 입력의 해시, 매니페스트, 감사 체인, Cosign 서명 | 장기 보존을 위한 WORM 저장소와 KMS 감사 로그 필요 |
| 오래된 PASS 증적 재사용 | 서명된 평가 시각을 배포 시각과 다시 비교하고 정책의 최대 증적 나이를 초과하면 실제 변경 전에 차단 | 중앙 저장소의 보존과 폐기 정책 필요 |
| 오래된 예외의 영구 사용 | 최대 기간, 연장 횟수, 취소, 보상 통제, 독립 승인자 | 정기 재검토 잡과 소유자 알림 필요 |
| 동시 배포 충돌 | GitLab 리소스 그룹, Jenkins 동시 빌드 차단, DAST 잡별 고유 리소스 | 두 CI를 함께 운영하려면 외부 분산 잠금 필요 |
| 배포 후 서비스 불능 | 롤아웃 확인, 서명된 상태 확인 URL로 스모크 테스트, 정확한 이전 다이제스트와 애너테이션 복원 | 비가역 DB 마이그레이션에는 expand-contract 절차 필요 |

## 주요 선택

- 핵심 로직은 Python 3.11 표준 라이브러리만 사용해 폐쇄망 설치 부담과 실행 시 의존성 범위를 줄였습니다.
- 스캐너 실행과 정책 판정을 분리해 도구를 교체해도 배포 기준이 바뀌지 않도록 했습니다.
- 라이선스 인벤토리는 취약점 탐지 건수에 포함하지 않고 별도로 집계합니다.
- 보호 릴리스는 Cosign을 요구하고, HMAC은 외부 의존성 없는 로컬 시연에만 남겼습니다.
- 정책을 즉시 교체하지 않고 섀도 판정으로 기존 정책과 후보 정책의 결과를 비교할 수 있게 했습니다.
