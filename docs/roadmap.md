# 단계별 개선 이력과 로드맵

## 외부 승인과 서명 경계 — 완료

- ITSM 승인 증명서를 전체 `ChangeRequest` 해시, `ReleaseSubject` 해시, 발급 시각에 결속했습니다.
- 운영 릴리스 정책은 허용된 ITSM 발급자, Cosign 서명 방식, 키 ID만 인정합니다.
- 외부 승인 개인키를 CI에 주입하지 않고 공개키로만 검증합니다.
- 최종 증적도 KMS 또는 Vault URI를 사용한 Cosign으로 서명하고, 배포 러너에는 PASS 증적 검증 공개키와 별도의 배포 결과 서명키를 제공합니다.

## 개발자 피드백과 정책 비교 — 완료

- GitLab Code Quality 및 SARIF 내보내기 결과를 제공합니다.
- 기준 정책과 후보 정책에서 발생한 위반 및 지문의 변화를 비교합니다.
- `--shadow-policy`는 기존 판정을 바꾸지 않고 후보 정책 결과를 증적에 함께 보존합니다.
- MR은 운영 승인을 요구하지 않는 전용 정책으로 실패 원인을 빠르게 보여줍니다.

## 배포 안전성과 운영 지표 — 완료

- Kubernetes 컨텍스트와 네임스페이스를 명시하고 `auth can-i` 사전 권한 검사를 통과한 경우에만 배포를 진행합니다.
- 승인된 상태 확인 URL을 대상으로 재시도 가능한 스모크 테스트를 실행합니다. 실제 배포 결과의 서명을 강제하며, 롤아웃, 스모크 테스트, 결과 서명 중 하나라도 실패하면 정확한 이전 이미지와 감사 애너테이션을 복원합니다.
- 게이트, 심각도, 예외, VEX, OSS 인벤토리, 승인 증적 검증 지표를 Prometheus 형식으로 생성합니다.
- GitLab DAST 네트워크와 컨테이너 이름을 파이프라인 및 잡 ID별로 분리했습니다.

## 배포 수명주기 검토 반영

- SIGINT/SIGTERM에 대한 복구와 결과 기록을 추가하고 GitLab 운영 배포의 자동 취소를 해제했습니다.
- DAST 실행 전 동일 잡의 Podman 저장소로 다이제스트 이미지를 내려받습니다.
- 배포 결과와 서명 경로를 배타적으로 예약하고, 서명이 완성된 결과만 게시합니다. 덮어쓰기 경합과 실패 시 다른 작성자의 파일 보존을 검증합니다.
- 이미지 변경 전 복구 정보를 보존하며, 서명 서비스 장애 때도 롤백 상태를 확인할 수 있습니다.
- kind와 실제 Cosign을 사용하는 별도 통합 테스트와 CI 잡을 추가했습니다. 보안 보고서 및 승인 입력은 예제이며 외부 ITSM/KMS의 운영 검증은 남아 있습니다.
- 정책 판정을 역할별 모듈로 나누고 CLI 옵션과 정책 모델, 정책 검증을 분리했습니다.

## 다음 우선순위

### P2: 실제 외부 시스템 통합

1. ITSM API와 IdP 그룹을 연결해 승인자의 현재 직무를 검증합니다.
2. 현재 각 스캐너 잡이 직접 발급하는 HMAC 증명서를 플랫폼 워크로드 아이덴티티와 스캐너별 단기 키로 교체합니다.
3. 정책 번들과 스캐너 규칙 세트를 별도 공급망 증적으로 서명하고 해시 허용 목록을 자동으로 관리합니다.
4. Dependency-Track, FOSSA 또는 사내 OSS API에 SBOM을 전송하고 법무 승인 상태를 조회합니다.

### P2: 공급망 재현성

1. `requirements-dev.lock`에 포함된 정확한 버전을 아티팩트 해시와 함께 관리하고 `--require-hashes`를 적용합니다.
2. 폐쇄망 패키지 미러 스냅샷과 컨테이너 반입 목록을 릴리스 증적에 추가합니다.
3. OCI 레지스트리에 SLSA 출처 증명, SBOM, VEX, 판정 결과를 참조 아티팩트로 게시합니다.

### P3: 운영 플랫폼

1. 증적을 WORM 또는 객체 잠금 저장소로 자동 이관하고 색인합니다.
2. Prometheus Pushgateway와 SIEM 어댑터를 추가하고 SLO와 경보 기준을 정의합니다.
3. GitLab과 Jenkins를 함께 운영하는 경우를 위한 외부 분산 배포 잠금을 도입합니다.
4. 비가역 데이터베이스 변경을 위한 expand-contract 검증과 연습 환경 복구 테스트를 추가합니다.

## 완료 판정 기준

다음 작업은 코드가 존재한다는 이유만으로 완료 처리하지 않습니다. 실제 외부 시스템의 신뢰 경계를 통과하는 통합 테스트와 키 회전, 장애 대응 사례, 런북, 감사 로그까지 확인해야 완료입니다.
